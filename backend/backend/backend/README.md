# Library System API

ASP.NET Core 8 Web API implementing the documented Library System backend:
Books, Borrowing Requests, Notifications, RabbitMQ-driven borrow processing,
SignalR real-time admin notifications, and a periodic due-date reminder job.

## Prerequisites

- [.NET 8 SDK](https://dotnet.microsoft.com/download)
- SQL Server (LocalDB, a full instance, or the Docker image below)
- RabbitMQ (Docker image below is easiest)

Quickest way to get SQL Server + RabbitMQ running locally with Docker:

```bash
docker run -d --name library-sql -e "ACCEPT_EULA=Y" -e "SA_PASSWORD=YourStrong!Passw0rd" -p 1433:1433 mcr.microsoft.com/mssql/server:2022-latest

docker run -d --name library-rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:3-management
```

If you use the SQL Server container above, update the connection string in
`appsettings.json` to use SQL auth instead of `Trusted_Connection`:

```
"DefaultConnection": "Server=localhost;Database=LibrarySystemDb;User Id=sa;Password=YourStrong!Passw0rd;TrustServerCertificate=True;"
```

## First-time setup

```bash
cd LibrarySystem.Api
dotnet restore

# Install the EF Core CLI tool once, if you don't have it:
dotnet tool install --global dotnet-ef

# Create the initial migration (this generates the SQL schema from the models)
dotnet ef migrations add InitialCreate

# Run the API — Program.cs applies migrations and seeds demo data automatically on startup
dotnet run
```

Swagger UI opens automatically at `https://localhost:7080/swagger`.

## Trying it out

1. `POST /api/auth/login` with the user account → copy the `token`.
2. Authorize in Swagger with `Bearer {token}`.
3. `GET /api/books` to find a `bookId`.
4. `POST /api/borrow` with `{ bookId, userId, borrowingPeriodDays }` — this
   creates a Pending request and publishes a message to RabbitMQ.
5. The background consumer picks that up, creates an admin notification, and
   pushes it live to any admin connected to `/hubs/notifications` via
   SignalR.
6. Log in as the admin account, `GET /api/requests` to see it, then
   `PUT /api/requests/{id}/approve` or `/deny`.
7. The borrower gets a `RequestApproved`/`RequestDenied` notification, and
   (if still within the borrowing period) a `BorrowDueReminder` a couple of
   days before the due date, generated by the hourly background job.

## Connecting to SignalR from the Angular frontend

```ts
import * as signalR from '@microsoft/signalr';

const connection = new signalR.HubConnectionBuilder()
  .withUrl('https://localhost:7080/hubs/notifications', {
    accessTokenFactory: () => yourJwtToken
  })
  .withAutomaticReconnect()
  .build();

connection.on('ReceiveNotification', (notification) => {
  console.log('New notification', notification);
});

await connection.start();
```

## Project layout

```
LibrarySystem.Api/
├── Controllers/        Auth, Books, BorrowingRequests, Notifications
├── Models/              EF Core entities (Book, User, BorrowingRequest, Notification)
├── DTOs/                 Request/response contracts matching the API spec
├── Data/                 DbContext + demo seed data
├── Services/             Business logic (validation, pagination, filtering)
├── Messaging/             RabbitMQ publisher + background consumer
├── BackgroundJobs/    Due-date reminder hosted service
├── Hubs/                  SignalR NotificationHub
├── Auth/                  JWT settings + token generation
└── Common/             Global exception → error-envelope middleware
```

## Notes / deliberate additions beyond the original doc

- **`POST /api/auth/login`** was added since every endpoint requires a JWT
  Bearer token but the original doc didn't specify how to obtain one.
- **`Book.AvailableCopies`** is decremented on approval and restored logic
  would need a `PUT /api/requests/{id}/return` endpoint if you want to model
  returns — not in the original spec, easy to add if you need it.
- All list endpoints return the documented paginated envelope
  (`{ items, page, pageSize, totalItems, totalPages }`) and all errors use
  the documented `{ code, message, details, traceId }` shape.
